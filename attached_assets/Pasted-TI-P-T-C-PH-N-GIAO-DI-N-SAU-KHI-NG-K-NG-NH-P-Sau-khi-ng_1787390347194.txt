TIẾP TỤC PHẦN GIAO DIỆN SAU KHI ĐĂNG KÝ/ĐĂNG NHẬP

Sau khi người dùng đăng ký tài khoản bằng email + mật khẩu và đăng nhập thành công, chuyển người dùng vào trang “Bảng điều khiển”.

LƯU Ý QUAN TRỌNG:
- KHÔNG dùng đăng nhập bằng Google.
- Tài khoản là tài khoản đăng ký trực tiếp bằng Email + Mật khẩu.
- Giữ nguyên hệ thống đăng ký/đăng nhập đã làm trước đó.
- Không tự ý thay đổi logic xác thực hiện tại nếu không cần thiết.
- Chỉ tiếp tục xây dựng giao diện và chức năng Dashboard theo đúng mô tả dưới đây.
- Giao diện phải responsive, ưu tiên hiển thị đẹp trên điện thoại giống ảnh mẫu.

==================================================
1. LAYOUT TỔNG THỂ
==================================================

Sau khi đăng nhập:

URL/page:
- /dashboard

Header trên mobile:

Bên trái:
- Icon menu hamburger.

Ở giữa:
- Tiêu đề “Bảng điều khiển”.

Bên phải:
- Nút “Nâng cấp”.
- Icon đăng xuất.

Header có đường kẻ phân cách phía dưới.

Giao diện nền sáng, sạch, hiện đại.
Bo góc nhẹ.
Border màu xám rất nhạt.
Shadow nhẹ.
Font hiện đại, dễ đọc.

==================================================
2. MENU SIDEBAR
==================================================

Khi bấm icon hamburger thì mở sidebar từ bên trái.

Sidebar giống ảnh mẫu:

Phần đầu:
- Logo Telegram Campaign.
- Tên: “Tele Campaign”
- Phụ đề: “Quản trị Telegram”
- Nút X để đóng menu.

Các menu:

1. Bảng điều khiển
   Icon dạng dashboard/grid.
   Đây là mục đang được chọn.
   Background xanh nhạt.
   Chữ xanh đậm.

2. Tài khoản
   Icon user.

3. Tài khoản Telegram
   Icon users.

4. Nhóm
   Icon group.

5. Mẫu tin nhắn
   Icon message/document.

6. Chiến dịch
   Icon campaign/megaphone.

7. Proxy
   Icon proxy/server.

8. Nhật ký
   Icon list/log.

Cuối sidebar:

Khung “Ngôn ngữ”

Có 2 lựa chọn:
- 🇻🇳 VI
- 🇬🇧 EN

VI được chọn mặc định.

Bên dưới:
“Tele Campaign v2.0”

Sidebar phải hoạt động tốt trên mobile.
Khi click X hoặc vùng overlay thì đóng sidebar.

==================================================

+ Fix camp bị đứng không chạy
+ fix lỗi đồng bộ tin nhắn đã lưu khi dùng proxy

Update ngày 6/6/2026 - 16h30:
+ Thêm chức năng proxy HTTP/SockS5 để acc clone an toàn và sống trâu hơn
+ Tối ưu ram server để web ổn định hơn

+ Update nâng cấp máy chủ

Update ngày 20/5/2026 - 12h00:

Nội dung thông báo phải lấy được từ database/admin sau này, không hard-code.

==================================================
8. NÚT NÂNG CẤP
==================================================

Trên header có nút:

“Nâng cấp”

Thiết kế:
- nền xanh đậm
- chữ trắng
- bo góc
- nổi bật nhưng không quá to.

Khi click:
- chuyển tới trang nâng cấp/gói dịch vụ.

Nếu trang nâng cấp chưa được xây dựng thì tạo route /upgrade và để sẵn giao diện placeholder.

==================================================
9. ĐĂNG XUẤT
==================================================

Icon logout ở góc phải header.

Khi click:
- đăng xuất khỏi session hiện tại.
- xóa session/token phù hợp.
- chuyển về trang đăng nhập.

Không được để người dùng quay lại Dashboard bằng nút Back sau khi logout nếu session đã hết hạn.

==================================================
10. BẢO VỆ DASHBOARD
==================================================

Dashboard phải là protected route.

Nếu chưa đăng nhập:
→ tự động chuyển về /login.

Nếu đã đăng nhập:
→ cho phép truy cập /dashboard.

Nếu token/session hết hạn:
→ logout và chuyển về /login.

Không để dữ liệu dashboard bị truy cập trực tiếp khi chưa xác thực.

==================================================
11. DATABASE / BACKEND
==================================================

Chuẩn bị cấu trúc để Dashboard lấy dữ liệu thật.

Các dữ liệu cần có:

- users
- telegram_accounts
- groups
- message_templates
- campaigns
- campaign_logs
- admin_notifications

Dashboard cần API để lấy:

- tổng số tài khoản Telegram
- tổng số nhóm đang hoạt động
- tổng số mẫu tin nhắn
- tổng số chiến dịch
- số tin đã gửi hôm nay
- số tin thất bại hôm nay
- chiến dịch gần đây
- nhật ký gần đây
- thông báo admin

Không hard-code số liệu Dashboard trong code frontend.

==================================================
15. KHÔNG ĐƯỢC PHÁ PHẦN ĐÃ LÀM
==================================================

Trước khi sửa code:

1. Kiểm tra cấu trúc project hiện tại.
2. Kiểm tra hệ thống đăng ký/đăng nhập đã làm.
3. Giữ nguyên authentication hiện tại.
4. Không xóa các route/chức năng đang hoạt động.
5. Không tạo thêm hệ thống authentication thứ hai.
6. Chỉ bổ sung Dashboard và kết nối với authentication hiện tại.

Nếu cần thay đổi file quan trọng:
→ giải thích ngắn gọn file nào sẽ thay đổi và tại sao.

Sau khi hoàn thành:
- kiểm tra build
- kiểm tra lỗi console
- kiểm tra login → dashboard
- kiểm tra logout → login
- kiểm tra protected route
- kiểm tra responsive mobile
- kiểm tra sidebar
- kiểm tra tất cả nút/menu.

NẾU CÓ LỖI:
- tự sửa lỗi.
- không được tự ý xóa chức năng để né lỗi.

VÀ QUAN TRỌNG:
Nếu thay đổi mới làm hỏng giao diện hoặc authentication hiện tại, phải ưu tiên khôi phục trạng thái hoạt động trước đó thay vì tiếp tục sửa chồng lên.
